# Build log — 2026-10-24

## Meeting Notes: persisted transcript + AI summary + `/notes/:id` (backlog item #3)

Closes the gap flagged in `BUILD-LOG-2026-10-23.md`'s "Remaining backlog" #3. The
live caption/Whisper transcript (`app/src/server.js` `caption` socket event +
`getWhisperTranscription`) only ever lived inside each peer's own browser tab,
carried peer-to-peer over the WebRTC DataChannel — the server never saw it, and it
was gone the moment every tab closed. There was already a client-only "Save
messages" button that downloads the transcript as a local `.txt`/JSON file
(`downloadCaptions()`), but nothing shareable and nothing summarized.

Built end to end, with real server logic and a real live call to the already-wired
OpenAI-compatible relay (not a stub) — verified by running the actual dev server and
exercising every new route with curl, not by adding automated tests.

- `app/src/meetingNotes.js` (new): on-disk JSON store, same pattern as
  `roomLink.js`/`roomClaims.js` — no database in this fork. Each record: id,
  `manageToken` (random 24-byte hex, compared with `crypto.timingSafeEqual` over a
  sha256 digest so length never leaks), roomId, createdAt, the normalized/capped
  transcript array, AI `summary` + `actionItems` + `summaryStatus`. Self-prunes
  (age + record-count caps) on every write — no new background timer.
- `app/src/server.js`:
  - `POST /api/v1/notes` — validates roomId, saves the transcript via
    `MeetingNotes.createNote`, then best-effort calls the same `chatGPT` client
    already instantiated for VCPeer Coworker (free `ai-relay-worker` by default) to
    generate `{summary, actionItems}` as JSON. The raw transcript is saved and
    servable regardless of whether the summary call succeeds — `summaryStatus` is
    one of `ready`/`failed`/`unavailable`. Returns `{ id, url, manageUrl,
    summaryStatus }`.
  - `GET /api/v1/notes/:id` — public read (never returns `manageToken`).
  - `DELETE /api/v1/notes/manage/:manageToken` — token-gated delete.
  - `GET /notes/:id` — serves the new static viewer page.
  - 3 new limiters in `app/src/middleware/rateLimiter.js`
    (`notesCreateLimiter`/`notesViewLimiter`/`notesDeleteLimiter`).
  - New `config.meetingNotes` section in `config.template.js` (+ local `config.js`,
    gitignored): size/retention caps, `MEETING_NOTES_DATA_DIR` env override
    following the same `*_DATA_DIR` convention as the other JSON stores.
- `public/views/notes.html` + `public/js/notes.js` + `public/css/notes.css` (new):
  dependency-free client-rendered viewer, same pattern as
  `public/js/clips/watch.js`/`watch.css` — loading/error/loaded states, copy-link
  button, summary + action-items sections (hidden if not ready), full transcript,
  and a delete button that only renders when `?manageToken=` is present in the URL
  (never discoverable from the plain share link).
- `public/views/client.html` + `public/js/client.js`: new "Share meeting notes"
  button in the caption panel's dropdown menu (next to the existing "Save
  messages"/"Clean messages" actions), wired to a new `shareMeetingNotes()` that
  POSTs the in-memory `transcripts` array + `roomId`, then shows the resulting
  shareable link in a Swal with a "Copy link" action (same Swal/`axios` pattern as
  the existing `maybeOfferRoomLink()`).
- `.gitignore` / `deploy/README.md`: `app/data/meeting-notes.json` added to the
  same never-commit / never-overwrite-on-redeploy list as `room-links.json`/
  `room-claims.json`/`notify.json`/`launchboard.json`.

Verified live against a real dev server (not mocked):
